**阶段 0 未通过验收。** 十四个工作包都已审计，十四条架构决策也已记录，但方案的验收清单并未满足。两个决策处于阻塞状态，另有一项条件——worker 与 agent 的生命周期关系——已有进展但尚未关闭。

审计本身已经完成。缺少的不是证据，而是方案在阶段 1 开始之前所要求的决策。

## 阻塞条件

方案列出七项禁止进入阶段 1 的条件。

| # | 条件 | 状态 |
|---|---|---|
| 1 | 无法确定浏览器资源的归属 | 已解除 —— 所有权是实时 agent 对象，由共享运行时强制，并由它自己的测试覆盖 |
| 2 | 无法确认跨 session 工具调用隔离 | 已解除 —— 作用域化的执行处理器强制了它，并有测试覆盖 |
| 3 | 无法确定 worker 与 agent 的生命周期关系 | **部分解除** —— worker 是子进程且不需要 agent，但它引出的审批问题依然存在 |
| 4 | 无法证明危险操作的审批发生在操作之前 | **未解除** —— 接缝存在，它在轮次内的顺序也已确立，但后台分支尚未定义 |
| 5 | 无法确定网络访问的强制执行位置 | 已解除 —— 强制执行位置是上游浏览器上下文的请求拦截；剩下的是它的重定向覆盖 |
| 6 | 无法保证新增包满足实验性包策略 | 已解除 —— 命名、登记条目与发布规则均已确定 |
| 7 | 无法确认现有测试与本地用户修改之间的边界 | 已解除 —— 没有改动任何被跟踪的源码文件，唯一的本地改动就是本次审计自己的文档目录 |

条件 3 与 4 共享同一个根因：审批服务要求开启的轮次，而后台 worker 没有轮次。

## 阻塞其余部分的那一个决策

三条记录归结为同一个问题：**后台 worker 如何获得有效的审批上下文？**

审批服务在 session 没有开启轮次时拒绝请求，且这一拒绝发生在任何应答者被咨询之前。因此，一个在 agent 轮次之外运行用例的 worker 完全无法使用该服务。

[审批、权限与凭据审计](approval-security-audit.zh.md)给出了三种设计及其代价：在 agent 的轮次内批准、在一次运行开始前批准整次运行，或者给 worker 一个带轮次语义的 session。这个选择决定 worker 的执行模型，而 worker 的执行模型又决定阶段 2 所需的进程隔离，因此不能推迟到阶段 1 之后。

阶段 1 必须把它记录为一条带验收标准的已定决策，并且不得在记录之前开始实现 worker。

## 第二项开放事项：重定向覆盖

上游所有者声明来源选项不影响重定向，也不是安全边界。强制执行位置已知，因此方案中的第五项条件已解除，但保证并未获得。

阶段 1 必须增加一个测试：导航到一个允许的来源，跟随一次到不允许来源的重定向，并记录观察到的行为。在该测试存在之前，包 README 必须声明白名单不覆盖重定向。

## 阶段 1 边界

ADR-011 中的审批决策确定之后，阶段 1 即可开始。在此之前，它不得开始 worker 的实现。

阶段 1 不修改既有的浏览器核心包。来源选项必须加入提供方自己的参数构造，而该变更属于提供方的包，不属于 TestPilot；如果提供方无法修改，TestPilot 必须改为通过共享注册面挂载自己的提供方。

阶段 1 交付：

| 交付项 | 依据 |
|---|---|
| 测试项目与用例领域 | ADR-007、ADR-008 |
| 带版本、身份与有效期的快照注册表 | ADR-004 |
| 拒绝过期引用的定位器校验器 | ADR-004 |
| 覆盖实测工具的风险分类 | ADR-004、ADR-011 |
| 在浏览器调用之前运行的审批门禁 | ADR-011 |
| 传给提供方的来源白名单，并附一个重定向测试 | ADR-010 |
| attach endpoint 的主机检查 | ADR-010 |
| 通过附件存储保存的证据 | ADR-012 |

阶段 1 不交付 worker 池、测试报告或失败分析。那些属于后续阶段。
