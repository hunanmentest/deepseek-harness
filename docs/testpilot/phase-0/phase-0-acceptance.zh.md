# TestPilot 阶段 0 — 验收

[English](phase-0-acceptance.md) | 中文

本文记录阶段 0 是否满足实施方案中的验收标准，并陈述阶段 1 的边界。

## 结论

**阶段 0 未通过验收。** 方案中的七项阻塞条件有三项未满足，其中一项无法在阶段 0 内关闭。

审计本身已经完成：仓库状态、浏览器提供方、MCP 契约、session 与 agent 生命周期、审批机制、安全边界、依赖版本与测试基线都已带证据记录。缺少的不是证据，而是方案在进入阶段 1 之前所要求的一个决策与一个强制点。

## 阻塞条件

方案列出七项禁止进入阶段 1 的条件。

| 编号 | 条件 | 状态 |
|---|---|---|
| 1 | 无法明确浏览器资源归属 | 已解除 —— 所有权是实时 `Agent` 对象，由 `SessionResources` 强制，并由 `resources.spec.ts` 与 `agent-disposal.spec.ts` 覆盖 |
| 2 | 无法确认跨 session 工具调用隔离 | 已解除 —— 作用域化的 `tools/execute` 处理器强制它，且 `mcp.spec.ts` 覆盖它 |
| 3 | 无法明确 worker 与 agent 的生命周期关系 | **未解除** —— 该关系尚未解决，且取决于审批问题 |
| 4 | 无法证明危险操作审批发生在操作之前 | **未解除** —— 接口可用，其在轮次内的顺序也已确立，但后台执行分支未定义 |
| 5 | 无法明确网络访问强制执行位置 | 已解除 —— 强制位置是上游 `context.route` 拦截；剩下的是它的覆盖范围，而非它的位置 |
| 6 | 无法保证新增包不违反 Experimental Package Policy | 已解除 —— 命名、登记与发布规则已确定，包存在后 `pnpm run constraints` 将予验证 |
| 7 | 无法确认现有测试和本地用户修改的边界 | **未解除** —— 该树没有 Git 元数据 |

条件 3、4 与 7 仍然开放。条件 3 与 4 共享同一个根因：审批接口要求开启的轮次，而后台 worker 没有轮次。

## 阻塞其余部分的那一个决策

三项开放条件归结为同一个问题：**后台 worker 如何获得有效的审批上下文？**

`dsh-user-approval` 服务在 session 没有开启轮次时拒绝请求，且这一拒绝发生在任何应答者被咨询之前。因此在 agent 轮次之外运行用例的测试 worker 完全无法使用该接口。

[审批与安全审计](approval-security-audit.zh.md) 给出了三种设计及其代价。这个选择决定 worker 的执行模型，而 worker 的执行模型又决定阶段 2 所需的进程隔离，因此不能推迟到阶段 1 之后。

阶段 1 必须把它记录为一条带验收标准的架构决策，并且不得在记录之前开始实现 worker。

## 第二项开放事项：重定向覆盖

上游所有者声明来源选项不作用于重定向，且不是安全边界。强制位置已知，因此方案中的阻塞条件 5 已解除，但保证并未获得。

阶段 1 必须增加一个测试：导航到一个被允许的来源，跟随重定向到不被允许的来源，并记录观察到的行为。在该测试存在之前，包 README 必须声明白名单不覆盖重定向。

## 第三项开放事项：仓库状态

工作树不含 `.git` 目录，因此方案中标注的 commit 基准无法确认，任何本地修改也无法与已提交状态区分。本次审计中的"已核实"因此表示"在当前存在的文件中已验证"。

阶段 1 必须从带 Git 元数据的树开始，并在改动任何生产代码之前重新确认基准 commit。

## 阶段 1 边界

三项开放条件关闭后，阶段 1 可以开始。在审批决策被记录之前，它不得开始 worker 的实现。

阶段 1 不修改既有的浏览器核心包。来源选项必须加入提供方的参数构造，而该变更属于提供方自己的包，不属于 TestPilot；若提供方无法修改，TestPilot 必须改为通过 `ctx.browserUse.register(...)` 挂载自己的提供方。

阶段 1 交付：

| 交付项 | 依据 |
|---|---|
| 一个 `TestProject` 与 `TestCase` 领域 | ADR-003 |
| 带版本、身份与 TTL 的快照注册表 | ADR-005 |
| 拒绝失效引用的定位器校验器 | ADR-005 |
| 覆盖实测 24 个工具的风险分类 | ADR-008 |
| 在浏览器调用之前运行的审批门禁 | ADR-004 |
| 传给提供方的来源白名单，以及一个重定向测试 | ADR-006 |
| attach endpoint 的主机检查 | 执行隔离审计的 attach 章节 |
| 通过附件存储保存的证据 | ADR-009 |

阶段 1 不交付 worker 池、测试报告或失败分析。那些属于后续阶段。
